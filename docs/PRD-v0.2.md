# GeoServer 自动发布工作台 — v0.2 开发基线

状态：开发原型基线。第一批交付以实际能力和验证记录为准。

## 产品目标

让实施人员在授权内网内，将已整理的 SHP、独立 GeoTIFF 和 SLD 发布到 GeoServer，获得真实 WMS 验收图、可追踪任务及明确的目录接入产物。数据处理在本机完成，源文件保持不变。

## 首版范围

- Python 统一核心、CLI、Windows 优先 PySide6 桌面界面。
- 受控 GDAL 3.13.3；Windows/Linux 运行时分别锁定。
- 单个和批量 SHP、多个独立 GeoTIFF；不把多 TIFF 自动拼接。
- 现成 SLD 和默认简单样式；可选工具不可用不阻塞基本发布。
- REST 上传、显式工作空间、精确服务对象和默认样式绑定。
- 同名停止、明确跳过、固定名称的新版本发布。
- WMS 1.1.1 实图验收；按需对矢量进行 WFS 抽样。
- SQLite 持久化意图、对象快照和操作结果。响应丢失不等于失败。
- 目录绑定清单；经人工核验字段映射后导出 SQL，不连接业务数据库。
- 首版支持配置对象清理，保留实际服务器数据文件；不声称恢复任意历史数据。

## 首版不包含

QML/LYRX/CIM 自动转换、Mosaic/Pyramid、已有数据原位替换、自动写业务库、直接编辑 data_dir、集群、共享目录/SFTP、多用户审批。

## 用户流程

主入口：发布任务、环境设置。

1. 选择数据：文件/目录导入，自动发现独立资源。
2. 检查与预览：组件、编码、CRS、字段、样式、名称映射及阻断问题。
3. 发布与结果：一次任务级确认后执行，显示实际地图、服务名称、未完成资源与目录登记状态。

高级参数和日志折叠。任务状态与业务目录状态分别显示。

## 已冻结的行为

- 没有 CRS 时阻断或要求显式声明；默认 CRS 不自动覆盖原生信息。
- 已存在 CRS 与声明不一致时阻断，不执行隐式重投影。
- 上传就是具有服务端副作用的写操作，PUT 同样受未知结果对账规则约束。
- 配置快照不等于数据备份；不开放原位 replace。
- 时间戳/任务版本名称在生成计划时固定，恢复时不重算。
- skip 不表示本次输入生效，也不自动认领既有对象。
- WMS 无法确定内容有效时显示待人工检查，不以文件大小作为成功依据。
- 取消在安全检查点生效。没有承诺任意上传位置暂停/续传。
- 锁仅协调同一个本地任务库；不能隔离管理员和其他电脑的外部操作。
- 恢复/清理需比较对象语义指纹及 SLD 正文摘要；外部变化转人工。
- SQL-only 阶段没有真实写库回执，不生成冒充可自动恢复的 DELETE。

## 当前预检深度

首版结构预检不等于完整空间数据质检。尚未进行全量无效几何扫描、拓扑修复、历史字段截断恢复、完整 SLD XSD 校验或视觉等价判定。报告必须展示这些边界。

## 验收门槛

1. 受控运行时版本/驱动、中文路径、GBK/UTF-8 验证。
2. 点、线、面 SHP 与单 RGB GeoTIFF 在真实 GeoServer 基线上发布成功。
3. 图像能解码、尺寸符合、实际内容不为空；合法空图进入人工核验。
4. 同任务重复执行不新增写操作。
5. 模拟服务端完成上传但客户端丢失响应：停止并对账，不盲重试。
6. 对象被外部修改时，不删除、不自动恢复覆盖。
7. 清理只移除本任务拥有的服务配置，不影响无关图层。
8. Windows/Linux 单元测试及桌面无界面冒烟；原生安装体验另行验收。

## 后续优先级

优先完成 Windows 运行时和便携包验证；随后按真实需求增加大文件传输、已知目录结构的 ImagePyramid 兼容、QML 有限转换、已有图层更新与缓存一致性。普通 FileGDB 优先评估 OpenFileGDB，不统一绑定 ArcGIS 许可。
