# 整个 GDB/MXD 批量发布、图幅审核及业务目录树

当前保留原始发布能力：源文件仅在本机离线转换为多个 SHP，每个 SHP 经独立检查后可发布为一个 GeoServer 图层。**源图层 != 地质图幅**，前者是发布对象，后者是业务目录的地学单元。

## 实施人员使用流程

1. 在发布工作台选择 **选择整个 GDB / 选择 MXD 地图**。GDB 由本机受控 GDAL/OpenFileGDB 只读转换，MXD 在安装 ArcMap 10.x/ArcPy 且原始数据源可访问的 Windows 主机导出 SHP/LYR。失败项隔离，成功项基于转换报告加入本地清单。
2. 如果一个 SHP 图层包含多个图幅编号，先执行 **按图幅字段拆分 SHP**。只读核查并人工确认编号字段，按实际属性值拆成多份独立 SHP，验证每份数量、字段、EPSG 和范围，严格保存完整报告（见 [属性分幅指南](FIELD-SHEET-SPLIT-P0B.md)）。然后点击 **下一步：检查图幅**。这是按每个发布图层校验 EPSG、字段、编码、样式和目标名，不能自动证明图幅数量。
3. 点击 **核对图幅关系**。表格显示源文件、源图层、候选编号字段。实施人员通过图幅编号和空间数据确认，选择已核对、未核对或需拆分；多图层同一图幅可多选并批量填同一编号。保存新的、绑定 `plan.json` SHA256 的本地审核 JSON。详细步骤参见 [P0-B 图幅归组指南](SHEET-REVIEW-P0B.md)。
4. 点击 **确认并发布** 时，仅按已确认的不可变计划发布 GeoServer 图层；同名会阻断，写操作未知时必须核对，不能盲目重试。
5. 查看实际 WMS 验收图后点 **生成数据库目录草稿**。若有完整的图幅审核清单，目录将按真实图幅归并多图层；如未审核，则只保留来源文件与图层级草稿，不宣称完成图幅分组。业务数据库登记单独审核，参见 [P0-A 数据库登记](CATALOG-REGISTER-GATE.md)。

## 生成的多级目录示例（所有节点默认待审核）

```text
待分类（本机审核容器）
└── 图幅集：基础地质.gdb              ← 该来源文件一个父节点
    ├── 图幅：H49E001006              ← 图幅节点按真实编号人工确认
    │   ├── 地层面                    ← GeoServer 图层 1
    │   └── 地质界线                  ← GeoServer 图层 2
    └── 图幅：H49E001007
        ├── 地层面_007
        └── 地质界线_007
```

跨 GDB/MXD 同名来源不合并；同一源文件内相同图幅编号才可归并。业务系统可能需要“专题 → 比例尺”节点，必须先核对数据库现有目录，替换 `draft_unclassified` 和待核对父节点，再审核每个 GeoServer WMS 实图。

## 必须明确的限制

- 一层含多张图幅时，**不能靠填写一个图幅编号代替几何/属性拆分**。当前只允许记录「需拆分」，阻止声称已确认全部图幅；后续需要实现经审核的属性字段分幅和数量/范围验证。
- MXD 只引用数据源，不能把 MXD 当成自带全部地质数据。复杂 LYR 样式、注记及图幅接缝的实际效果需在授权的 ArcMap/QGIS 和 GeoServer 上验收。
- 本地转换报告、`plan.json`、人工图幅审核 JSON 必须保持 SHA256 匹配；草稿始终设置 `classification_reviewed=false`，MXD/GDB 设置 `conversion_reviewed=false`，WMS 仍待验收，`schema_verified=false`。
- 正式业务数据库节点确实**写入 PostgreSQL**，但必须在只读核验、WMS 审阅和显式二次授权之后才允许执行受控 SQL；没有现场授权时只使用合成测试库，禁止把生产 GDB/MXD/SHP、数据库密码发送至公网。

此流程采用 Ponytail 原则复用现有 GDAL/ArcPy、不可变发布计划、目录草稿和事务登记，不新增依赖或后台服务。
