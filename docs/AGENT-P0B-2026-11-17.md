# GeoPublisher Workbench：P0-B 图幅语义与桌面主题推进（2026-11-17）

> Ponytail：The best code is the code you never wrote. 先复用 plans、catalog_draft、business_tree、GDB/MXD 报告与现有 Qt 页面，不引入新服务或依赖。

## 目标

当前“GDB/MXD 每个导出的 SHP → 一个目录子节点”只是图层关系，不应称为真实地质图幅。建立离线、可审核的逻辑图幅分组：用户明确确认一个图层属于哪个图幅，多图层同图幅自动归并；当一个图层包含多张图幅，明确标记待拆分、阻止以错误关系注册。

## P0-B 本轮可验收边界

1. 基于已冻结的 plan.json 的 resource_id、原文件来源、原图层名称、manifest SHA 建立图幅审核清单，不能仅凭文件名自动判定图幅。
2. GDB 优先提取可能的图幅编码属性字段（仅“候选”，不代表值或空间边界已核验）；MXD 参考原数据框/图层名称但不推断真实编号。
3. 在桌面审核清单中明确输入图幅编号、名称并选择状态（已核对/待核对/需拆分）。相同源文件且相同图幅编号的图层共享一个图幅节点。不同源文件的同名图幅不能错合并。
4. `catalog_draft` 只有在合法、匹配 plan 摘要的审核清单下，才采用图幅归组；结构为**真实业务父节点（待审核）→ 来源 GDB/MXD 父节点 → 已核实图幅节点 → 各 GeoServer 图层**。为保持一个图幅可包含多个服务，图幅下允许多层；没核验的不得声称实际图幅数。
5. 即便所有编号人工确认，数据库目录仍 `schema_verified=false`、`classification_reviewed=false`、WMS 待验收、不可直接写库，且“需拆分”项阻断自动按图层生成图幅节点。
6. Qt 按钮最小触点、不同宽度溢出、浅色/深色背景、主按钮禁用与高对比度状态保持一致；保留原简洁风格，不能因打开更多工具/主题切换导致按钮截断。
7. 使用离线合成计划、模拟 MXD/GDB、Qt headless 验证；不访问/上传现场真实图件、不连接生产数据库。
8. 完成 CI / Windows 便携版 / 快捷方式版本更新，旧版可回退。

## 明确未完成的能力

本轮不实现“依据 GDB 属性自动准确拆分所有地质图幅”或“多 GeoServer 图层合成为一张 WMS 图”的无条件自动化。若图层含多个逻辑图幅，需另行按审核字段拆分和各子集数量/范围核验，不能伪装自动完成。
