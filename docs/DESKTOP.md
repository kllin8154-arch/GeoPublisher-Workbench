# 桌面版使用说明

桌面版使用与 CLI 相同的预检、计划和执行引擎。首版提供 Windows 优先的 PySide6 界面；Linux 可运行桌面原型，但安装包和发行版兼容性仍需单独验证。

## 安装与启动

在已准备 Python 3.11 或更新版本的项目环境中安装桌面依赖：

```bash
python -m pip install '.[desktop]'
geopub-desktop
```

开发环境也可使用：

```bash
uv sync --extra desktop --extra dev
uv run geopub-desktop
```

GDAL 命令不由界面在线下载安装。请在环境设置中明确指定经过验证的受控工具目录与版本。外网断开的现场需事先准备完整的 Python、Qt、GDAL/PROJ 运行时和依赖包。

Windows 使用系统中的微软雅黑等中文字体。Linux 桌面还需事先安装可显示中文的字体，例如 Noto Sans CJK SC；缺少中文字体时 Qt 会显示方框。字体依赖应随离线部署环境准备，应用不会在线下载。

## 首次设置环境

打开左侧“环境设置”，填写环境标识、GeoServer 根地址、既有工作空间、GDAL 命令目录和预期版本。HTTPS 默认验证证书；自签名环境可指定 CA 文件。确实使用 HTTP 的授权内网环境需要明确勾选允许 HTTP。本地回环测试地址可以使用 HTTP。

凭据有两种输入方式：

- 填写“本次用户名”和“本次密码”，只在当前进程内使用。
- 留空上述两项，从档案中指定的环境变量读取，默认名称为 `GEOPUB_USERNAME` 和 `GEOPUB_PASSWORD`。

保存的环境 JSON 仅包含变量名引用，不保存凭据值。载入另一个档案时会清空会话凭据。不要把含有真实密码的连接串粘贴到 GeoServer 地址栏。

默认任务目录在 Windows 有 D 盘时使用 `D:/a系统测试/GeoPublisher-Workbench`；其他情况使用当前工作目录下的 `data`。可自行选择产物目录。启动时不会扫描用户的数据文件或创建任务目录。

## 三段发布流程

### 1. 选择数据

拖入或选择 SHP、GeoTIFF 文件，也可明确选择目录。多个 TIFF 默认要求确认；只有确定它们应分别成为独立图层时，勾选“将所选 TIFF 分别发布为独立图层”。更改数据列表会清除确认，重复添加同一路径不改变已有选择。组件完整性、坐标系、编码和实际可读性由数据预检检查。

已知 Mosaic/Pyramid 结构及其辅助索引会阻断，即使单独选择其中一个文件或已经勾选分别发布。系统不会把尚未识别的目录自动认定为可拼接服务。详细边界见 [多 TIFF 导入说明](RASTER-IMPORTS.md)。任务输出位置必须位于导入目录之外。

可选现成 SLD；留空时生成简单默认样式。SHP 默认使用 `.cpg` 中声明的编码，没有可确认声明时需明确选择 GBK 或 UTF-8。仅当已确认源数据缺少坐标系时填写声明 CRS；坐标声明不会执行重投影。

同名策略包括停止、跳过和创建独立新版本。首版不提供原位替换。WFS 验收默认关闭，可按目标服务能力显式启用。

点击“检查并生成计划”后，后台生成独立任务目录、不可变发布副本和 `plan.json`。源文件保持不变。检查期间界面仍可响应，不会通过强制结束转换进程来实现暂停。

### 2. 检查与预览

查看目标 GeoServer、工作空间、图层名称、数据类型、坐标系和预检结果。存在阻断问题时执行按钮不可用。调整数据或环境后，旧计划会失效，需要重新生成。

执行前会统一显示目标、总资源数量和已确认的 TIFF 独立图层数量，确认后才进行发布。此阶段没有模拟地图冒充真实预览；实际 WMS 地图在发布验收后显示。

### 3. 发布与结果

发布由后台线程调用统一引擎，显示资源和阶段信息。安全取消会请求引擎在安全检查点停止；当前不可中断请求仍需完成或超时，界面不会把响应丢失判定为未执行。

完成后显示实际返回的任务状态、资源结果、存在的 WMS PNG 验收图，以及任务报告入口。没有验收图或需要人工核对时会明确显示，不会生成假预览或把部分成功显示为完全成功。

目录 SQL 即使生成，也需要独立核对与登记，不能据此认定业务系统已可见。

## 恢复任务与历史

点击“恢复任务”选择已有任务的 `plan.json`，界面会校验计划哈希并展示冻结的目标。执行时仍需确认，并由引擎核对源文件、发布副本和服务端状态。原来的会话凭据不会随计划恢复，需要重新输入或配置环境变量。

新计划会恢复原来的导入方式和资源数量，当前数据表单的勾选不会覆盖它。原导入目录增加、减少或重命名数据、出现结构标记时，执行会停止并要求重新预检。旧版多个 TIFF 的计划未记录分别发布的确认，恢复后禁止继续发布；已有任务仍可按原计划和任务记录执行 CLI 配置清理。

任务历史读取当前产物目录下的 `geopublisher.sqlite`，与 CLI 的同目录任务共享日志和锁。双击历史任务可载入对应计划。任务目录已迁移或文件缺失时应先按报告核对，不要手工改写计划哈希来强行继续。

## 后台任务运行时关闭窗口

本地检查或 GDB 转换未结束时点击关闭，会询问是否在当前操作完成后自动关闭。选择“是”后，窗口先保持打开，当前线程自然结束后自动关闭；不会强制杀掉 GDAL 或删除转换产物。选择“否”继续使用当前界面。

GeoServer 发布过程中点击关闭，会询问是否请求安全取消，并在任务停止后自动关闭。安全取消只在检查点生效：正在等待的网络请求可能需要等到受控超时，服务端写入结果不确定时仍要在任务历史/日志中进行人工核对。**不要通过任务管理器强制结束程序来代替安全取消。**

已经选择“任务结束后自动关闭”时，成功/失败回调不再打开额外确认框；窗口关闭前清除内存会话凭据。窗口关闭不意味着任务已经成功发布。详见 [专项验证记录](VALIDATION-CLOSE-WHILE-RUNNING-2026-11-02.md)。


## LYR 样式的批量转换

在 **发布任务 → GDB / MXD / LYR 转换** 对话框里选择 **导出 QGIS LYR→SLD 批量离线转换脚本**，得到 `qgis_lyr_to_sld.py`。把同名的 SHP 与 ArcMap LYR 保存在同一个本地文件夹，且 SHP 的 SHX、DBF、PRJ、CPG 组件齐全；使用**本机 QGIS 自带的 Python 启动器**（不是系统 Python）：

```powershell
& "D:\QGIS\bin\python-qgis.bat" "D:\LocalGIS\qgis_lyr_to_sld.py" "D:\LocalGIS\mxd-export" "D:\LocalGIS\sld-new"
```

这只是本机的安装路径示例。脚本依赖用户自行安装的 QGIS Style Assistant 和 SLYR Community；输出全新目录内含按原 SHP 文件名命名的 QML、SLD 及 `lyr-conversion-report.json`，失败中间文件单独保留。完成后在工作台高级选项中选中**批量 SLD 目录**再预检。脚本不发送数据、不覆盖来源、不自动执行 GeoServer 发布。

已在 ArcMap 10.8 + QGIS 4.2.1 的真实合成点线面样本中成功导出 3 份样式，中文路径及 SHA256 原文件不变测试通过；更复杂的地质分类、字体标注及 WMS 视觉一致性仍需人工核对。详细条件和限制见 [GDB/MXD/LYR 离线转换说明](IMPORT-GDB-MXD-LYR.md)。
