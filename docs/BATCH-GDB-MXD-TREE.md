# 整个 GDB / MXD 批量图幅发布与父子目录

本阶段沿用 Ponytail 原则：复用现有 GDAL/ArcPy 转换器、多资源 GeoServer 发布计划与业务目录草稿生成器；不增加新的服务端写入步骤。

## 实施人员操作（Windows/macOS/Linux 客户端，具体 GIS 转换依赖本机）

1. 在“数据导入”选择 **整库批量导入（GDB / MXD / LYR）**。
   - **GDB**：本机 GDAL/OpenFileGDB 只读列出要素类，默认勾选可导出的非空矢量图层；注记、缺 EPSG、空数据按现有规则提示并跳过。生成每层单独的 SHP 与字段对照.csv。
   - **MXD**：必须能访问 MXD 原始数据源，Windows ArcMap/ArcPy 导出每个可用矢量图层为同名 SHP + LYR。缺失数据源、服务图层、含定义查询的子集等会提示或停止；不会伪造 MXD 内没有的几何。
   - **LYR**：配合本机 QGIS 将对应样式转换为 SLD；样式与复杂标注不能保证无损。
2. 完成并检查转换报告，确认把**整批成功导出的 SHP**加入当前发布任务。跳过/失败的图层不会被悄悄算作成功；需要查报告、处理后再生成任务。
3. 点击 **检查数据**：既有 `build_plan()` 对每个 SHP 独立生成 `r0001/r0002/...`、独立存储名、样式和本机校验副本，批次统一确认后逐个发布。重复目标名会阻止创建计划，不会覆盖旧图层。
4. **确认并发布**：仍只在明确确认后向授权 GeoServer 写入；每个图层拥有独立状态、WMS 验收结果和日志。失败/结果不确定时必须核对，不可盲目重发。
5. 结果页点击 **生成业务目录初稿**，得到以下待审核结构：

```text
待分类（临时）
└── 图幅集：湖南基础地质.gdb（待核对）     ← 整个来源文件的父节点
    ├── 第1幅                              ← SHP / GeoServer 图层1
    ├── 第2幅                              ← SHP / GeoServer 图层2
    └── 第3幅                              ← SHP / GeoServer 图层3
```

多个 GDB/MXD 文件对应多个独立父节点，不按相同文件名误合并。子节点的 `code` 仍是安全的 GeoServer 图层标识，`title` 优先保留 ArcGIS 原图层名称。单独导入的、无法核对来源报告的 SHP/TIFF 仍留在临时根节点，不伪造 GDB/MXD 来源。

## 不可省略的核对

- 这个映射默认是**一个导出的要素类/矢量图层 → 一个独立 GeoServer 图层**。若**一个要素类内实际上包含多张图幅**，不能按图层数声称已发布全部图幅；需另行按核实的图幅编号字段拆分，并验证要素/空间范围。
- 来源转换报告须与每一个 SHP 一一匹配；GDB 还须匹配 SHP SHA256；MXD 须存在对应 LYR。重复、缺失、转换失败或被修改的清单会阻断后续计划或执行。转换报告哈希也记录在不可变 `plan.json` 的 source-hash 校验内。
- `draft_unclassified` 是临时审核容器。必须先确认实际**专题 → 比例尺 → 图幅集父节点**，将图幅集移入正确的业务父节点、删除未分类容器，再审核各子节点顺序、名称、比例尺、WMS PNG/样式/中文注记及 GeoServer 服务映射。
- GDB/MXD 数据来源在草稿中标为 `source_format=gdb/mxd`，`publish_kind=shapefile`，并设置 `conversion_reviewed=false`。人工复核字段/样式后才能变更；`schema_verified=false` 和 `wms.visual_reviewed=false` 仍保持未批准。
- **不自动创建真实数据库父节点、不执行 SQL。** 必须先对 206 执行只读字段/目录检查、备份并获得明确授权，SQL 仍单独生成及执行。现场图件、GDB/MXD/SHP 和服务器密码均不能提交到公共仓库。

## 当前限制

此版本提供批量导出、逐图层 GeoServer 发布和**来源文件父子目录草稿**，不是对一个包含多张图幅记录的单一要素类进行智能图幅切分。不同来源存在同名 GeoServer 图层时沿用“停止”策略，必须先解决命名冲突。正式 208/206 仍需在局域网进行获授权的连接和人工验收。
